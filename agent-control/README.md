# Riva Agent Control Layer

A local, developer-only CLI for operating this repository with AI agents in
the loop. It is **not part of the Riva healthcare product** — it is
infrastructure that lives beside `backend/` and `Riva-master/`, never inside
them, and can be deleted (`rm -rf agent-control tasks CLAUDE.md AGENTS.md
docs/RIVA_PRODUCT.md docs/RIVA_ARCHITECTURE.md ...` — see the full list in
`RIVA_AGENT_IMPLEMENTATION_REPORT.md`) without touching the product at all.

Full design rationale: `docs/RIVA_AGENT_WORKFLOW_AUDIT.md` (written before
this existed). How the human+agent workflow is meant to use it day to day:
`docs/RIVA_AGENT_WORKFLOW.md`. Security posture: `docs/RIVA_SECURITY.md`.

## What this is

- A Node.js CLI (`bin/riva-agent.mjs`), zero dependencies beyond Node's own
  built-ins (`fs`, `path`, `child_process`). No `npm install` needed to run
  it — it uses nothing that isn't already required for the Angular project.
- **No HTTP server, no listening socket, nothing bound to any port —
  localhost or otherwise.** You run commands directly; nothing is ever
  reachable over a network. If a local HTTP interface is ever added later,
  it must bind to `127.0.0.1` only and is a deliberate future decision, not
  something this phase implements — see `docs/RIVA_AGENT_WORKFLOW.md`
  ("Future MCP Integration").
- Confined to this repository by construction: every path the CLI touches is
  resolved and checked against the repo root before use, and `.env`/secret
  -like filenames are refused outright (`lib/workspace.mjs`).
- Aware that this project currently has **no git repository** on the real
  machine (see the audit, §4) — git-dependent commands (`branch`, `diff`)
  detect this and explain what to do rather than failing confusingly.
- Recognizes eight categories of restricted operation (migrations, dependency
  installs, file deletion, env/config changes, prod deploy, payment config,
  auth changes, destructive DB ops) and **refuses all of them unconditionally
  — there is no approval flag this tool understands.** A human runs those
  commands themselves. See `lib/restricted.mjs`.

## Requirements

Node.js (already required for the Angular frontend — any reasonably current
version works; this was tested with Node 22). For the `test`/`lint` backend
commands: PHP + Composer with `backend/vendor/` already installed (same as
running the Laravel app normally). No new dependency is installed by this
tool for either.

## Start / stop

There is nothing to "start" — it's a CLI, invoked per command, and exits
when the command finishes. There is nothing to "stop" — no background
process, no daemon, no server.

```
node agent-control/bin/riva-agent.mjs help
```

Run from the repository root (or with paths adjusted — the CLI resolves its
own root from its install location regardless of your current directory).

## Commands

See `node agent-control/bin/riva-agent.mjs help` for the live list, or
`RIVA_AGENT_IMPLEMENTATION_REPORT.md` at the repo root for the full
walkthrough with examples of each command actually run.

## Layout

```
agent-control/
├── bin/riva-agent.mjs      CLI entry point
├── lib/
│   ├── workspace.mjs       root resolution + path/secret confinement (everything routes through this)
│   ├── git.mjs             git wrapper — fixed argv only, never a shell string
│   ├── tasks.mjs           task board read/write
│   ├── restricted.mjs      restricted-operation registry + refusal messages
│   └── report.mjs          engineering report generator
├── config/workspace.json   human-readable description of the confinement (not read by code)
├── templates/TASK_TEMPLATE.md
└── reports/                generated by `riva-agent report`, gitignored-worthy scratch output
```
